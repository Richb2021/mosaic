# Adaptive support and voice tutor

Mosaic suggests a next focus and an amount of support from first responses in the saved programme and its selected, reviewed practice/Explore resources. Distinct question text is counted once. Incorrect answers, uncertainty and recorded help request more support; two different confident, correct responses without recorded help suggest fewer prompts, and three including a transfer response suggest a further application. These are transparent study heuristics, not scores, mastery claims or an inferred ability level. Written reasoning remains for human review. Learners can override the suggestion without altering their answers.

The connected itinerary and new Muse requests use the same server-derived suggestion. Profile interests, goals, starting point, accessibility preferences and stated difficulties remain in the evidence-bound creative context. Text-first/reduced-motion preferences and due revisit questions retain priority. Existing games and reviewed question banks are not silently rewritten.

The programme now opens the tutor at its recommended activity. Voice input is optional: record or choose at most 60 seconds, explicitly permit Fish transcription, edit the transcript, and separately ask Muse. Browser audio is converted to bounded mono 16 kHz PCM WAV; the server validates the actual format and duration before provider work. Raw input audio is not stored by Mosaic. Owner-bound transcripts are saved as existing knowledge records, available as saved voice drafts, and included in export, deletion and retention. Provider-side processing remains subject to the provider's terms.

Muse Wonder (`muse-wonder-1.0`, Standard) remains the tutor. Fish `transcribe-1-pro` handles transcription; the configured synthetic guide voice on `s2.1-pro` speaks replies. Tutor replies remain labelled unreviewed AI guidance. Exact canonical reply text is split only when needed, version-bound and cached through the existing private audio store. Replay does not regenerate. Transcription and new narration use the existing request/cost budgets, idempotency and no-automatic-retry rules.

Adults with author access can use the tutor. A managed learner needs their organiser's explicit tutor setting in Welcome; default is off, and transferring a learner resets it. Tutor permission does not grant source, game, podcast or cartoon authoring. Authentication, source/assignment access, learner ownership and data epochs still apply. A tutor interaction since the previous first response marks the next practice/Explore response as assisted; later fresh responses can be recorded separately.

No migration or new provider is required. The optional support preference uses the existing NoCodeBackend programme record with version conflicts. Membership uses the existing organiser record. Audio and transcript lifecycle reuse the existing media/knowledge mechanisms.

Validation and limits are recorded in `../../output/adaptive-voice/` in the workspace. Synthetic adult cases test implementation, not learning efficacy. Hardware microphone permission/capture and assistive-technology speech output need their own device testing; responsive browser checks do not prove those. Independent audit was attempted through the fleet route but returned no findings within its four-minute bound, so it is not counted as a passed audit.
