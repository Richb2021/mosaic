# Media persistence and data controls

Narration uses a private object store (`BUCKET`) with ownership/revision metadata in the application SQL store (`DB`). The pre-migration deployment uses Sites R2 and D1; [deployment status](DEPLOYMENT.md) tracks their replacement. The SHA-256 cache identity includes Sites owner, NCB learner digest, script ID and approved hash, segment, voice ID, Fish model and synthesis recipe. The browser never supplies arbitrary narration text. R2 keys are never public URLs. Replay checks storage before budget admission or Fish invocation. Missing/failed bytes are explicit; no automatic paid replacement is sent.

`Your data` in the studio exports account records, source-linked creative work and saved MP3 clips as ZIP. Workspace exports contain extracted source text, chapter copies and optionally retained originals within the [knowledge-library export bounds](KNOWLEDGE-PROGRAMME.md). Exports over 100 MB of audio fall back to JSON plus individual clip downloads. The sign-in account and credentials are outside these exports.

Deletion previews bind exact IDs/counts to a hash. Owner-scoped mutation leases prevent deletion during active writes; lifecycle epochs reject stale clients. Cleanup is resumable after partial failure. Active R2 bytes are deleted and checked before their metadata is removed. NCB deletion reads owner-filtered rows, deletes only owned IDs and verifies disappearance. Deleting a source cascades to its generated chapters, your creative episodes and narration. If another learner has a derived episode, source deletion is blocked until that learner removes their copy. Personal cleanups lock only that learner; a pending workspace cleanup is visible and resumable to signed-in learners of the same Sites owner. Learning progress and already-downloaded/offline copies are separate and explicitly disclosed.

Known Meta response IDs are deleted through the supported Responses DELETE endpoint; An explicit `response_not_found` error is idempotent absence; ambiguous404/410 responses remain pending rather than claiming deletion. Provider failures remain visible for retry after local content has been removed. Fish synthetic voice presets are shared infrastructure and are not removed with a learner’s recordings. This is not a provider-wide zero-retention guarantee or a promise about infrastructure backups.

Retention is independently configurable for audio (creation), creative scripts/conversations (last edit), NCB profile/save slots (latest write) and sources (creation, with descendants). Choices are keep-until-deleted or 7/30/90/365 days. Default preserves existing data. Cleanup is checked at most hourly during ordinary authenticated reads, and immediately on the Your data screen. It is not run before writes, and concurrent saves defer the automatic sweep. Partial progress retention preserves offline device copies but marks them for explicit review before another upload. The background retention runner also sweeps registered workspaces, including inactive ones, when enabled. Scheduler outages can delay cleanup. See [operations](LAUNCH-OPERATIONS.md) and [deployment status](DEPLOYMENT.md); a configured flag alone is not proof the runner is healthy.

Deleted AI jobs retain only content-free quota receipts until the original 24-hour rolling window ends; manual copies retain their non-inference marker. Minimal data-action history and completed cleanup receipts are retained for 30 days, with expired rows swept during visits or background maintenance. A failed provider cleanup retains the response ID until resolved. Password/account management continues through NoCodeBackend.

References checked 1 Nov 2026: [R2 Workers API](https://developers.cloudflare.com/r2/api/workers/workers-api-reference/), [Meta response deletion](https://dev.meta.ai/docs/api-reference/responses/delete-response). NCB endpoints follow the existing checked-in `docs/ncb/swagger.json` contract. No private book content is used as product evidence.

Tutor narration uses canonical saved reply text and its versioned cache recipe. It remains unreviewed guidance, even when spoken. Optional voice-input transcripts use the existing knowledge-record lifecycle; raw voice-input recordings are not retained by Mosaic. See [adaptive voice](ADAPTIVE-VOICE.md).
