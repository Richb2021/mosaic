# Reviewed course routes

My courses → Plan this course creates a course-wide route from reviewed sources linked to its topics. The organiser selects the actual passages, confirms scope, and requests a Muse Wonder proposal. Profile starting point, stage, context, interests, struggles, exam context, time and access preferences are a saved snapshot. They do not infer ability or impose a learning style.

## Explicit scope

Up to 12 unique linked sources, 24 selected passages and 32,000 excerpt characters per plan. The UI reports selected/omitted passages and unavailable or unreviewed sources. The model reads this packet for meaning and proposes relationships between objectives and source IDs. This is **not full-library semantic retrieval** and there is no claimed recall score or exhaustive syllabus coverage. The existing Find passages facility remains lexical. Larger courses need to be split or planned in bounded courses; no source is silently truncated into the request.

At most six objectives, each bound to a notebook topic and up to 12 passages from three sources within the chapter's 18,000-character budget. Prerequisites must point to earlier objectives. Every objective remains available; the route is suggested preparation, never a gate or grade. Missing requested coverage stays visible, including after approval. A plan with no supported objectives cannot be approved.

## Review and handoff

Canonical citations are attached by the server, never generated by the model. The reviewer can edit objectives, rationale, preferred game format and prerequisite relationships without inference. Approval binds the exact plan hash and current source/course snapshot. Changing topics, goals, titles or source links invalidates the plan. Old plans remain readable until their normal lifecycle removes them. Linking an approved plan replaces the current route and clears its objective/chapter links; existing chapters and learner progress remain.

Prepare this activity opens the established chapter workshop with the exact objective, format and evidence selection. The organiser still confirms evidence, reviews the generated questions/game and publishes it. Only a published chapter generated from that exact objective and evidence can be linked back. Starting it creates or reopens the normal personalised programme; subsequent saved practice and delayed checks inform a transparent next-step suggestion. Game scores and wins do not count as understanding. Suggestions are bounded by current practice evidence, not a validated efficacy or mastery model.

## Storage and security

No database migration. The existing D1 workshop_jobs table stores recordType course-plan, source versions and recoverable Meta response identity. Existing cost ledger, request limit, idempotency, submission lock, no-auto-resubmit handling and 30-minute polling bound apply. The existing NoCodeBackend learner_profiles courses slot stores the exact approved plan and objective/chapter links, using version conflict protection.

Existing NCB author/adult, session identity, owner, origin and data-epoch controls apply. Managed learners keep the assigned-chapter flow; group-wide plan assignment and teacher progress reporting are separate work. Private Site audience is unchanged.

Source deletion and retention include derived plans; learner/workspace deletion includes their owned plans. Conversations/episodes/course-plans retention uses last saved modification time. Workspace export includes course plans on the first material page and binds them into the export snapshot. Learner export also includes owned plans because they contain personal context. No credentials are exported. Provider deletion and backups retain existing documented limits.
